# Passo 006 — Implementar expressões

## Situação

- Planejamento para revisão; implementação não iniciada.
- Passos 1 a 5 concluídos. Questões `006-Q01` a `006-Q07` em [QUESTIONS.md](QUESTIONS.md).
- Propostas dependem das respostas e de autorização explícita para implementar.

## Objetivo

Construir a AST de tabelas, expressões, predicados e ordenação, com composição imutável e validação estrutural independente de banco. Não gerar nem executar SQL neste passo.

## Contratos já definidos

- `Table(name)` retorna `TableRef`; `As(alias)` e `InSchema(schema)` retornam nova referência.
- `Column(name)` e agregações admitem `As(alias)`; `Value(v)` representa parâmetro.
- `Eq/Ne/Lt/Lte/Gt/Gte` recebem coluna `string` e valor `any`; variantes `*Expr` recebem duas expressões.
- `In/NotIn` recebem coluna e `...any`; listas vazias representam falso/verdadeiro, respectivamente.
- `Like/NotLike` recebem coluna e padrão `string`; `Between/NotBetween` recebem coluna e exatamente dois limites `any`; `IsNull/IsNotNull` recebem coluna.
- `And/Or/Where/On` recebem `...Predicate`; `Where/On` agrupam por AND. Grupos explícitos preservam parênteses; grupos vazios são inválidos.
- `Count/Avg/Sum/Min/Max` recebem coluna `string`; `Count` também admite `"*"`.
- `Asc/Desc` recebem coluna; `NullsFirst/NullsLast` configuram a posição de NULLs.
- Valores, inclusive NULL, seguem como parâmetros; não reescrever `Eq/Ne` para `IS NULL`, avaliar `driver.Valuer` ou corrigir semântica SQL.
- AST controlada pelo pacote; identificadores e valores separados. Não criar expressão de SQL arbitrário.
- Erros de estrutura são observados ao compilar/executar. As assinaturas dos construtores não retornam `error`.
- UPDATE/DELETE rejeitam WHERE ausente ou constante verdadeiro. `ErrMissingWhere` prevalece quando coexistir com `ErrInvalidQuery`; aplicação dessa política pertence aos builders de escrita.

Referências: [DEFINITIONS.md](DEFINITIONS.md), [MANUAL.md](MANUAL.md), decisões de [001.md](001.md) e organização de [002.md](002.md).

- Propor tipos concretos `struct` com estado privado, expostos por aliases na raiz; não interfaces implementáveis pelo utilizador.
- Métodos públicos somente os contratados: `Expr.As`, `TableRef.As/InSchema`, `OrderTerm.NullsFirst/NullsLast`. `Value` retorna `Expr`, também podendo receber alias de projeção.
- `Predicate` é distinto de `Expr`; não aceitar predicado como projeção nem expressão como grupo lógico por conversão implícita.
- Valores zero dos quatro tipos representam nós inválidos, detectados na validação. Não adicionar construtores ou campos públicos para nós arbitrários.
- Validadores e análise pertencem ao pacote interno; não acrescentar `Validate`, `Error`, `Build`, serialização ou getters à API pública deste passo.
- Dependências: raiz → `internal/expression` → `internal/errs`; sem dependência de conexão, transação, driver ou dialeto.
- Acesso da futura compilação aos nós será detalhado no passo 7, sem antecipar um compilador ou formato público de AST.

## API de construção proposta

Os retornos concretos dependem de Q01; nomes e argumentos preservam o catálogo existente.

```go
func Table(name string) TableRef
func (table TableRef) As(alias string) TableRef
func (table TableRef) InSchema(schema string) TableRef

func Column(name string) Expr
func Value(value any) Expr
func (expr Expr) As(alias string) Expr

// Mesmo contrato para Ne, Lt, Lte, Gt e Gte.
func Eq(column string, value any) Predicate
// Mesmo contrato para NeExpr, LtExpr, LteExpr, GtExpr e GteExpr.
func EqExpr(left, right Expr) Predicate

func In(column string, values ...any) Predicate
func NotIn(column string, values ...any) Predicate
func Like(column, pattern string) Predicate
func NotLike(column, pattern string) Predicate
func Between(column string, lower, upper any) Predicate
func NotBetween(column string, lower, upper any) Predicate
func IsNull(column string) Predicate
func IsNotNull(column string) Predicate

func And(predicates ...Predicate) Predicate
func Or(predicates ...Predicate) Predicate
func Where(predicates ...Predicate) Predicate
func On(predicates ...Predicate) Predicate

// Mesmo contrato para Avg, Sum, Min e Max.
func Count(column string) Expr
func Asc(column string) OrderTerm
func Desc(column string) OrderTerm
func (order OrderTerm) NullsFirst() OrderTerm
func (order OrderTerm) NullsLast() OrderTerm
```

## Validação e modificadores — 006-Q03

- Construtores preservam os dados; validadores internos examinam a árvore resultante e retornam erros compatíveis com `ErrInvalidQuery`, sem panic para entradas inválidas representáveis na API.
- Validar nós zero, nomes, operandos, grupos e contexto de uso. `nil` como valor de parâmetro é válido; não confundir `Value(nil)` com `Expr{}`.
- Não converter valores nem chamar `driver.Valuer`; incompatibilidade de valores permanece com `database/sql` na execução futura.
- Não incluir valores de parâmetros nos erros; mensagens identificam a categoria/caminho estrutural inválido.
- Validar na ordem dos operandos/itens, retornando o primeiro erro estrutural. Não ocultar erro de um ramo porque outro ramo determina uma constante booleana.
- `As`, `InSchema`, `NullsFirst` e `NullsLast` substituem apenas sua configuração anterior; a última chamada prevalece, sem modificar a versão anterior.
- Alias/schema omitido é válido; chamada explícita com string vazia é inválida. Não usar `As("")` ou `InSchema("")` para limpar configuração.
- Validar o estado final, sem acumular erro irremovível: `.As("").As("u")` pode corrigir o alias, mas não corrige `Column("")`.
- O passo entrega validadores internos; a observação pública dos erros ocorrerá com os builders/compilação posteriores, sem API provisória.

## Identificadores — 006-Q04

- `Table(name)`, `InSchema(schema)` e `As(alias)` recebem um componente, sem ponto. Qualificação de tabela usa explicitamente `InSchema`.
- `Column` e colunas recebidas pelos operadores, agregações e ordenação dividem nomes por `.`; rejeitar componentes vazios (`".id"`, `"u..id"`, `"u."`). Não impor quantidade máxima de componentes nesta etapa.
- Rejeitar nome vazio, componente somente espaços, NUL, UTF-8 inválido e `*` fora das posições aprovadas em Q05.
- Preservar maiúsculas, Unicode, espaços e caracteres de citação dentro de componentes não vazios; não interpretar aspas como delimitadores já escapados nem restringir nomes a uma expressão regular ASCII.
- Não remover espaços nem reconhecer fragmentos SQL: `Column("name DESC")` é um identificador literal, a ser escapado integralmente no passo 7.
- Não suportar ponto literal dentro de um componente por esta API; nomes com pontos representam qualificação. Existência de tabela/coluna e limites específicos do banco ficam para execução.

## Curingas e aliases por contexto — 006-Q05

| Construção                                                            | Regra proposta                                              |
| --------------------------------------------------------------------- | ----------------------------------------------------------- |
| `Column("*")`, `Column("u.*")`                                        | Somente projeção; `*` deve ser componente final. Sem alias. |
| `Count("*")`                                                          | Agregação válida; admite alias de projeção.                 |
| `Count("u.*")`, `Sum("*")` e demais agregações com curinga            | `ErrInvalidQuery`.                                          |
| Coluna em comparação, IN, LIKE, intervalo, teste de NULL ou ordenação | Sem curinga.                                                |
| Tabela, schema e alias                                                | Sem `*`.                                                    |
| `Expr.As(...)` em projeção                                            | Permitido para coluna, agregação e valor, exceto curinga.   |
| Expressão com alias como operando de `*Expr`                          | `ErrInvalidQuery`; não remover alias silenciosamente.       |

Validadores recebem contexto interno de uso (projeção ou operando), sem gerar SQL. Validade de agregação em WHERE versus HAVING e compatibilidade de NULLs na ordenação serão verificadas nas etapas dos builders/dialetos.

## Imutabilidade e valores — 006-Q06

- Copiar slices variádicos de filhos e valores ao construir nós; modificadores copiam o estado alterado. Nós imutáveis podem compartilhar subárvores.
- Não guardar slices do chamador como armazenamento mutável da AST nem expor slices internos para modificação.
- Cópia de `[]any` é superficial: ponteiros, mapas, slices (inclusive `[]byte`) e `driver.Valuer` dentro dos valores mantêm identidade/conteúdo referenciado.
- Não fazer deep copy, reflexão ou avaliação antecipada. A aplicação não deve modificar valores referenciados entre a construção e o fim da execução.
- AST reutilizável entre consultas; o vínculo com `Tx` pertence aos futuros builders, não aos nós independentes deste passo.

## Constantes e agrupamentos — 006-Q07

- Preservar grupos, ordem dos filhos e valores originais da AST; não reordenar, deduplicar ou apagar ramos.
- Análise interna separada classifica predicados em `AlwaysTrue`, `AlwaysFalse` ou `Unknown`. `Unknown` significa “não demonstrado pela análise”, não o valor SQL NULL.
- `In` vazio é falso; `NotIn` vazio é verdadeiro. Validar a coluna mesmo nessas listas vazias.
- AND: algum filho falso → falso; todos verdadeiros → verdadeiro; demais → desconhecido.
- OR: algum filho verdadeiro → verdadeiro; todos falsos → falso; demais → desconhecido.
- Grupos vazios/zero são inválidos, sem usar identidade matemática para aceitá-los. Outros operadores permanecem desconhecidos; não inferir tautologias como `EqExpr(Column("id"), Column("id"))`.
- Separar classificação e erro de validação para que ambos possam ser informados aos builders. Exemplo: OR com `NotIn("id")` e um ramo inválido mantém classificação verdadeira e erro estrutural; o futuro builder de escrita aplica a prioridade já aprovada de `ErrMissingWhere`.
- Não expor constantes booleanas como novos construtores públicos nem implementar agora a proteção de escrita ou `ErrMissingWhere`.
